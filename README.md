# Мини-учёт оплат учебного центра

[![CI](https://github.com/sty-alt/ecomdev-payments/actions/workflows/ci.yml/badge.svg)](https://github.com/sty-alt/ecomdev-payments/actions/workflows/ci.yml)

Тестовое задание на позицию разработчика в **Ecomdev**. Выбран **вариант Б — мобильная веб-страница**.

REST API для учеников и оплат, отчёт «должники за месяц», мобильная веб-страница (вариант Б) и Telegram-бот (вариант А, дополнительно).

**Стек:** Node.js 22, TypeScript, Fastify 5, Zod 4 (валидация + OpenAPI), SQLite (better-sqlite3), grammY, Vitest.

## Запуск

Нужен **Node.js 22 или новее** (`node -v`). Внешняя БД не нужна: SQLite-файл создаётся сам в `./data/payments.db`.

```bash
git clone https://github.com/sty-alt/ecomdev-payments.git
cd ecomdev-payments
npm ci
npm run seed      # демо-данные: 9 учеников, оплаты за прошлый и текущий месяц (необязательно)
npm run dev       # http://localhost:3000
```

- Веб-страница: http://localhost:3000/
- Документация API (Swagger UI): http://localhost:3000/docs
- Проверка работоспособности: http://localhost:3000/health

Сборка и запуск в продакшен-режиме:

```bash
npm run build
npm start
```

Через Docker (БД хранится в volume `payments-data`):

```bash
docker compose up --build
```

Тесты и проверка типов:

```bash
npm test
npm run typecheck
npm run lint
```

### Настройки

Скопируйте `.env.example` в `.env` — файл подхватывается автоматически. Все переменные необязательны.

В PowerShell: `Copy-Item .env.example .env`. В Linux/macOS: `cp .env.example .env`.

| Переменная                     | По умолчанию         | Назначение                                                                                                             |
| ------------------------------ | -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `PORT`                         | `3000`               | Порт HTTP-сервера                                                                                                      |
| `DATABASE_PATH`                | `./data/payments.db` | Файл SQLite                                                                                                            |
| `TZ_NAME`                      | `Europe/Moscow`      | Часовой пояс центра: от него зависят «сегодня» и «текущий месяц»                                                       |
| `ADMIN_USER`, `ADMIN_PASSWORD` | —                    | Логин и пароль (HTTP Basic Auth) на API, страницу и `/docs`. Не заданы — доступ открыт, это режим локальной разработки |
| `TELEGRAM_BOT_TOKEN`           | —                    | Токен от @BotFather; без него бот не запускается                                                                       |
| `TELEGRAM_ALLOWED_USER_IDS`    | —                    | Telegram ID через запятую, кому разрешён бот. Пусто — бот всем отказывает                                              |
| `TELEGRAM_ALLOW_ALL`           | —                    | `true` — пустить в бота любого (только для проверки)                                                                   |

Для публичного сервера задайте `ADMIN_USER` и `ADMIN_PASSWORD`: браузер сам покажет окно входа, страница продолжит работать без изменений. `/health` остаётся открытым для healthcheck. Basic Auth передаёт пароль в каждом запросе, поэтому снаружи сервис нужно отдавать только по HTTPS (через обратный прокси).

### Telegram-бот

1. Создайте бота у [@BotFather](https://t.me/BotFather) и запишите токен в `.env`: `TELEGRAM_BOT_TOKEN=...`
2. `npm run dev` — бот работает в том же процессе через long polling, вебхук и публичный адрес не нужны.
3. Команды: `/debt` — должники текущего месяца (`/debt 2026-09` — за другой месяц), `/pay 3 4500` — внести оплату сегодняшним числом (`/pay 3 4500,50 2026-10-01` — с датой), `/students` — список с id, `/help`.

Бот закрыт по умолчанию: он вносит оплаты и показывает телефоны учеников. Напишите ему что угодно — он ответит вашим Telegram ID. Впишите ID в `TELEGRAM_ALLOWED_USER_IDS` и перезапустите сервер. Для быстрой проверки можно временно поставить `TELEGRAM_ALLOW_ALL=true`.

## API

Суммы — в рублях, до двух знаков после запятой (`4500`, `4500.5`). Даты — `YYYY-MM-DD`. Если заданы `ADMIN_USER` и `ADMIN_PASSWORD`, добавляйте к curl `-u логин:пароль`. Ошибки всегда в одном формате:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Некорректные данные запроса",
    "details": [{ "field": "body.amount", "message": "Сумма оплаты должна быть больше нуля" }]
  }
}
```

| Метод и путь                        | Что делает                                                                          | Коды ответа        |
| ----------------------------------- | ----------------------------------------------------------------------------------- | ------------------ |
| `POST /students`                    | Создать ученика: `name`, `phone`, `group`, `monthlyFee`, необязательно `startDate`  | 201, 400           |
| `GET /students?group=&search=`      | Список; фильтр по группе, поиск по имени или телефону                               | 200                |
| `GET /students/:id`                 | Один ученик                                                                         | 200, 404           |
| `PATCH /students/:id`               | Изменить любые поля                                                                 | 200, 400, 404      |
| `DELETE /students/:id`              | Удалить ученика вместе с его оплатами                                               | 204, 404           |
| `POST /payments`                    | Добавить оплату: `studentId`, `amount`, необязательно `date` (по умолчанию сегодня) | 201, 400, 404, 422 |
| `GET /payments?studentId=&month=`   | Оплаты ученика, новые сверху; `month` — фильтр по месяцу                            | 200, 400, 404      |
| `GET /students/:id/payments?month=` | То же как вложенный ресурс                                                          | 200, 400, 404      |
| `GET /debtors?month=YYYY-MM`        | Должники за месяц; без `month` — текущий месяц                                      | 200, 400           |
| `DELETE /payments/:id`              | Отменить ошибочно внесённую оплату; возвращает отменённую запись                    | 200, 400, 404      |
| `GET /calendar`                     | Сегодняшняя дата и часовой пояс учебного центра для веб-интерфейса                  | 200                |

Примеры:

```bash
curl -X POST localhost:3000/students -H 'content-type: application/json' \
  -d '{"name":"Анна Смирнова","phone":"8 916 123-45-67","group":"Английский A2","monthlyFee":6000}'

curl -X POST localhost:3000/payments -H 'content-type: application/json' \
  -d '{"studentId":1,"amount":2500,"date":"2026-10-03"}'

curl 'localhost:3000/debtors?month=2026-10'
```

```json

      "group": "Английский A2",
```

## Правила расчёта

Задание оставляет часть правил открытыми — вот какие решения приняты и почему.
- **Оплата относится к месяцу по своей дате.** Несколько оплат за месяц суммируются. Переплата не переносится на следующий месяц: каждый месяц считается отдельно.
- **Должник** — ученик, у которого сумма оплат за месяц меньше месячной суммы. Долг = месячная сумма − оплачено. Список отсортирован по убыванию долга.
- **Ученик не должен за месяцы до начала занятий.** У ученика есть `startDate` (по умолчанию — дата создания). Новичок, пришедший 10 октября, не попадёт в должники сентября, а за октябрь платит полностью.
- **Деньги хранятся в копейках** (целые числа в БД), поэтому `0.1 + 0.2` не превращается в `0.30000000000000004` и не порождает «долг» в одну копейку.
- **Будущая дата оплаты запрещена** (422): нельзя записать оплату, которой ещё не было.
- **Телефон нормализуется** к виду `+79161234567`; `8 (916) 123-45-67` и `+7 916 123-45-67` — один и тот же номер.
- **Месячная сумма 0** допустима (бесплатное обучение) — такой ученик никогда не должник.
- **Изменение месячной суммы** влияет и на прошлые месяцы: история тарифов не хранится (см. улучшения).
- **Удаление ученика удаляет его оплаты** (`ON DELETE CASCADE`), чтобы в базе не оставались «осиротевшие» записи.
- **«Сегодня» и «текущий месяц»** определяются в часовом поясе `TZ_NAME`, а не по UTC: в 02:00 по Москве 1-го числа уже новый месяц.
- **Календарь страницы** получает дату и часовой пояс центра через `/calendar`, поэтому часовой пояс устройства не меняет месяц отчёта. Поддерживаются годы от `0001` до `9999`.

## Устройство

```
src/
  server.ts              точка входа: конфиг, БД, HTTP-сервер, бот, корректное завершение
  app.ts                 сборка Fastify: валидация Zod, Swagger, роуты, статика
  services.ts            общий контейнер сервисов для HTTP и бота
  students/              схемы, репозиторий (SQL) и роуты учеников
  payments/              схемы, репозиторий, сервис с бизнес-правилами, роуты
  debtors/               SQL-отчёт о должниках и роут
  bot/                   commands.ts — логика команд без Telegram; bot.ts — grammY и проверка доступа
  http/                  единый формат ошибок, Basic Auth
  db/                    подключение SQLite и миграции (PRAGMA user_version)
  lib/                   деньги, даты и часовой пояс, телефоны, ошибки
public/                  веб-страница без сборки: HTML + CSS + JS-модуль
test/                    тесты API, расчёта долгов, команд бота и утилит
scripts/seed.ts          демо-данные
```

Суммы оплат за месяц считаются одним SQL-запросом (`LEFT JOIN` + `GROUP BY`) по индексу `payments(student_id, paid_on)`. Из агрегированных строк учеников сервис формирует список должников и сводку месяца; отдельные записи оплат в память не загружаются.

Тесты поднимают приложение на SQLite в памяти и ходят в него через `app.inject`, «сегодня» зафиксировано. Отдельный тест проверяет сохранность данных после повторного открытия файловой БД. Покрыты CRUD и валидация, границы месяцев, частичные и множественные оплаты, переплата, новички, нулевой тариф, копейки, календарь браузера и часовой пояс, разбор аргументов и ограничение длины сообщений бота, Basic Auth, доступ к боту и разбор конфигурации. Актуальное количество выводит `npm test`.

### Что проверено и что нет

- Проверено: тесты, `typecheck`, `lint`, `build`, запуск собранной версии, веб-страница на ширине телефона 375 px и на десктопе. В браузере пройдены создание и изменение ученика, внесение и отмена оплаты, удаление ученика.
- Логика команд бота покрыта тестами, но на этой машине бот не запускался с настоящим токеном Telegram.
- Dockerfile написан по стандартной схеме, но собрать образ на машине разработки не удалось: Docker на ней не установлен.
- Чистая установка `npm ci`, сборка и тесты дополнительно проверены в отдельном временном каталоге без готовых `node_modules` и `.env`.

## Что бы я улучшил за неделю

1. **Период оплаты отдельно от даты.** Сейчас оплата 28 октября «за ноябрь» засчитается в октябрь. Добавил бы поле «за какой месяц» и перенос переплаты на следующий месяц с отображением баланса ученика.
2. **История тарифов и статусы учеников.** Хранить месячную сумму с датой начала действия, чтобы повышение цены не меняло долги прошлых месяцев. Вместо удаления — архивировать ученика (отчислен, на паузе), сохраняя историю оплат; пропорциональный расчёт для пришедших в середине месяца.
3. **Полноценные пользователи и журнал действий.** Вместо одного общего пароля (Basic Auth) — учётные записи администраторов с сессиями и ролями, запись «кто и когда внёс или изменил оплату». Сейчас отмена оплаты уже реализована через `DELETE /payments/:id`; добавил бы обязательную причину и сохранение отменённой записи в журнале.
4. **PostgreSQL и эксплуатация.** Перейти на PostgreSQL с миграциями (Drizzle или Kysely), добавить пагинацию списков, rate limiting, бэкапы, метрики и e2e-тесты страницы на Playwright.
5. **Напоминания должникам.** Еженедельная рассылка в Telegram администратору и, по согласию, родителям; кнопки «Внести» и «Напомнить» прямо в сообщении бота (inline-клавиатура) вместо ручного ввода `/pay`.
